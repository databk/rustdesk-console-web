## 行为与职责

RemoteInput 负责 DOM 焦点和物理输入事件。RemoteSession 独立跟踪当前加密会话中已经成功发送的按键和鼠标按钮。当原生输入权限为 false 时，所有输入继续被阻止。权限从 false 恢复为 true 时，会话先为此前发送且仍处于持有状态的输入发送释放事件，再向页面发布权限恢复消息。权限被拒绝期间尝试的点击、文本、移动或滚轮操作不会被缓存或重放。

重复 keydown 共用一条状态记录。上限为 256 个不同的按键和三个鼠标按钮；第 257 个不同的持键会在其按下事件发送前触发会话终止。原子文本输入不计为持键。正常清理只在仍有输入权限时尝试释放，发送失败也不能阻止套接字清理。关闭或重连会清空状态，权限仍被拒绝时也不例外。

四种支持的界面语言均会在全屏区域内显示撤权提示。权限恢复时，完成清理后才重新允许输入。提示说明：原生持键可能持续到权限恢复，或者被控设备上对应按键／鼠标按钮被实际按下并释放。浏览器不能绕过原生端已撤销的权限强制释放。

四组完成的测试均验证了以下行为：

- 真实拖动在受控 WinForms 文本框中选中 10 或 11 个字符；滚轮操作使首个可见字符位置从 0 变为 64。
- 原生端撤销输入权限前已经按住 Shift，撤权期间仍保持按下。页面移除了 Canvas 的键盘聚焦能力，并阻止输入尝试。
- 全屏时风险提示持续可见，画面连接仍正常。
- 恢复原生权限后，Shift 在脚本发送任何显式 Shift-up 之前自动释放。在下一次约 100 ms 的夹具采样中观察到释放；这是轮询观察结果，不是输入延迟基准。
- 被禁止的输入没有重放。重新点击 Canvas 后，普通键盘输入恢复；随后 Canvas 失焦会释放 Shift，断开连接会释放按住的鼠标左键。没有记录到页面异常。

此前两次测试脚本尝试仍保留在私有目录：一次遗漏表单 change 事件，导致鉴权阶段超时；另一次已经验证自动释放，但退出全屏后未重新获得焦点就发送了后续输入。修正脚本后，上述四组测试完成。没有通过修改产品代码绕过这两项测试准备问题。

本轮直接验证了真实 Shift 撤权／恢复和正常鼠标清理。三个鼠标按钮的撤权／恢复线协议行为均有加密单元测试覆盖，但不宣称已经实测完整的鼠标持键撤权矩阵或任意多客户端输入冲突。权限持续为 false 时，原生 1.4.9 此前发现的多连接清理问题仍然相关。
