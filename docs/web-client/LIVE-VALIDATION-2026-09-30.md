## 仅点击批准修正及本轮最终产物

原生协议在等待仅点击批准时发送 LoginResponse.error = No Password Access，并继续保持等待。若将所有非密码错误都视为拒绝，会在原生用户决定前关闭会话。RemoteSession 现在识别这一精确信号，保持加密连接，同时继续遵守已有认证期限。其他错误仍按失败关闭连接；重复提示不能延长期限。

相关上游定义固定为 rustdesk 提交 4812a9815bd3c6a93f3ad903f29504168c4930a1 的 src/client.rs（LOGIN_MSG_NO_PASSWORD_ACCESS、LOGIN_ERROR_MAP）及 src/server/connection.rs（ApproveMode::Click）。新增五项测试覆盖两个 KX 版本、拒绝、取消和有界等待。启用 detectOpenHandles 后，11 个套件、全部 81 项 Web Client 测试通过；代码风格与 TypeScript 检查通过，保留同样的 12 项无关警告。

本轮修正后的本地 Docker 镜像为 rustdesk-console-web:web-client-approval-local：

- Worker：web-client-worker.e1b1ae84.js，1497734 字节。

## 本轮已知限制

- 确认真实 KX 0 的修饰键边界情况：原生撤销键盘权限后，Windows 1.4.9 保留 Shift 按下状态。还有两个属于本次测试的连接存在时，关闭该测试连接后 10 秒内也未释放；另一个已授权且有输入权限的测试连接发送 Shift-up 后，测试程序确认释放。这是协议与 Worker 探测，不是完整生产界面测试。源码检查还表明，权限变为 false 后浏览器抑制释放消息。不能宣称撤权清理已解决、绕过原生权限，或添加一律断开的变通措施。后续单连接 1.4.9 检查同样在权限为 false 时保留 Shift，但关闭唯一连接后，在下一个 100 ms 探测点确认释放。本轮记录时，新版原生客户端的修饰键撤权行为及合适的客户端缓解措施尚未验证；后续进展见本文开头的输入恢复报告。未遗留任何测试修饰键按下状态。
