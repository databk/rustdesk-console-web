# 顶部菜单与文件浮窗使用说明

日期：2026-10-01，Asia/Shanghai。本轮替换旧右侧工具侧栏；协议、原生认证和五项扩展能力沿用现有实现。以下检查区分组件模拟与原生客户端验收，镜像身份以最终交付记录为准。

## 页面操作

未连接时直接显示两列设备选择，左侧输入 ID，右侧选择当前账号可见的设备。开始连接后画面占满工作台。

- 顶部中间的小把手可点击或移入展开菜单。图钉可固定；未固定时，指针和焦点离开、下拉菜单关闭后自动收起。显示、键盘、文件、声音、全屏和断开只展示当前已有能力。
- 菜单、说明和文件浮窗覆盖在画面内，不预留右侧或下方空间。全屏仍可操作。方向键、Home、End 可在工具按钮间导航，Escape 只在菜单/窗口内处理。
- 显示菜单切换显示器、恢复本地缩放；键盘菜单提供常用键、修饰键和软键盘 Unicode 输入。关闭菜单、失焦和隐藏仍按现有原生权限规则释放输入；被控端撤权时不能保证立即释放卡住的键。
- 左上第一行显示设备 ID 和连接状态，第二行以小标识显示适用的旧版加密。可悬停、聚焦或点击查看说明，文件会话的标识明确区别于桌面会话。

## 正常复制粘贴

本机复制文字或受支持 PNG 后，聚焦远程画面按 Ctrl/Cmd+V（或 Shift+Insert）即可发送粘贴操作。远端复制后，当前会话前台聚焦、权限允许时直接同步本机剪贴板。删除原文字/图片中转面板，不再要求用户打开工具复制。

浏览器拒绝写入时只显示简短“点击复制”，可通过用户点击重试。点击仍失败会保持失败提示，不报告成功。浏览器能力、权限与焦点条件各不相同，因此不能承诺后台无条件同步。

协调器串行写入、只保留最新排队内容，按内容去重以避免回环。失焦、隐藏、原生剪贴板撤权、账户/会话变化以及本机主动粘贴清除排队内容；独立 clipboardGeneration 同时使 Worker 中已开始但未完成的 PNG 转换失效。此代次不与显示代次混用。

已经调用浏览器 Clipboard API 的原子异步写入无法撤回。撤权/断开可阻止后续写入并清除迟到结果，不能保证浏览器已受理的那一次写入不完成。文字仍最多 1 MiB，PNG 编码最多 4 MiB、边长 4096、像素 4,194,304。

## 远端文件窗口

顶部文件入口打开页面内独立浮窗，标题显示“远端文件”和设备 ID。先单独连接文件会话并输入密码或等待被控端批准，桌面授权不能代替文件授权。

地址栏可以输入 Windows 盘符绝对路径并按回车，旁边提供上一级、刷新和打开目录。“/”显示驱动器列表。目录草稿与已加载目录分别保存，路径无效或远端拒绝时保留原列表，上传仍指向最后成功打开的目录。

单击选中，双击文件夹进入；键盘 Enter 也可进入已聚焦文件夹。下载必须点击“下载所选文件”。“上传到此文件夹”调用本机系统文件选择窗口，选中的本机文件上传到已加载远端目录。页内窗口不会冒充本机系统窗口能直接读远端磁盘。

窗口右上减号收起视图，文件会话、目录与传输进度保持。传输取消与窗口收起分开；断开桌面或文件会话仍按原约定清理资源。重名保留/覆盖、逐文件传输、流式保存与 16 MiB 回退限制沿用原实现。不新增删除、改名、递归目录或断点续传。

## 旧版加密说明

判定依据是签名验证后实际协商的 KX，不凭显示版本判断。KX0 双向密钥与计数值复用会影响保密性，显示提示并不修复该风险；它仍是加密连接，不等于已经窃听。

2026-09-30 已核验 RustDesk 1.4.9 仍使用旧交换，指定官方 1.5.0 nightly Windows 构建支持 KX1。nightly 资产 SHA-256：dc446869860d0ed0eb06355d248aa8fe4177642b8ff46a8ca66e57c69db1421b。该资产是滚动开发构建，不能仅凭版本号或 nightly 标签保证能力，也没有已核验的稳定修复版本阈值。升级目标是远端客户端，重连后看实际协商。

主会话以实际 React 页面组件、合成 Worker 和合成远端内容，在本机 Chrome 串行完成 27 项检查：电脑两种视口、390px 窄屏、全屏画面几何、同一 canvas、顶部菜单、文件浮窗、旧版说明、焦点与权限拒绝，以及实际 Clipboard API 的小段文字、4×4 PNG 写入和 Ctrl+V。旧剪贴板代次被丢弃，新上下文可以正常写入。没有连接 VPS 或原生 RustDesk，窄屏也不代表手机真机验收。

独立审查补充了剪贴板 A→B→A 顺序和权限拒绝后的回切回归；串行运行页面、菜单、剪贴板、Worker、设备列表 5 套件共 60 项通过，`--detectOpenHandles` 未报告未关闭句柄并正常退出。协议生成校验、修改范围 lint 和差异空白检查通过。本机完整类型检查仍因复用的旧 AntD/Umi 依赖及生成导出差异失败，必须在 GitHub Actions 的锁定依赖环境完成类型、完整测试、生产构建和镜像冒烟后才能交付。
